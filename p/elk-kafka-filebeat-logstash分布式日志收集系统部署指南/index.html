运维人员需要对系统和业务日志进行精准把控，便于分析系统和业务状态。日志分布在不同的服务器上，传统的方法依次登录每台服务器查看日志，既繁琐又效率低下。因此，我们需要集中化的日志管理工具，将位于不同服务器上的日志收集到一起，然后进行分析、展示。

认识ELK

ELK是一套开源的日志分析系统，由 Elasticsearch + Logstash + Kibana 组成。

官网说明: https://www.elastic.co/cn/products

  • Elasticsearch：基于 JSON 的分布式搜索和分析引擎，专为实现水平扩展、高可靠性和管理便捷性而设计。作为 Elastic Stack 的核心，它集中存储您的数据，帮助您发现意料之中以及意料之外的情况。
  • Kibana：能够以图表的形式呈现数据，并且具有可扩展的用户界面，供您全方位配置和管理 Elastic Stack。借助 Kibana 的交互式可视化，您可以先从一个问题出发，观察数据中的规律。
  • Beats：轻量型采集器的平台，从边缘机器向 Logstash 和 Elasticsearch 发送数据。将这些采集器安装在您的服务器中，它们就会把数据汇总到 Elasticsearch。如果需要更强大的处理性能，Beats 还能将数据输送到 Logstash 进行转换和解析。

ELK下载地址：https://www.elastic.co/cn/downloads

Elasticsearch

Elasticsearch（简称 ES）是一个开源的分布式搜索引擎，同时也是一个分布式文档数据库。它提供了大量数据的存储功能，以及快速的搜索与分析功能。

Elasticsearch 集群部署方式

单节点的 ES 在处理大量数据时需要消耗大量内存和 CPU 资源，容易出现处理瓶颈或宕机。为了解决单节点 ES 的性能瓶颈和单点故障，我们需要部署 ES 集群。

ES 集群的优点

  • 优化数据处理能力：通过多台 ES 共同处理数据，提升处理性能与效率。
  • 容错能力增强：解决了 ES 单点故障问题，使架构更为稳定。
  • 数据安全：分布式多副本存储，数据更安全。

节点规划

  • 主节点（master）：负责集群元数据管理、分片分配。
  • 数据节点（data）：存储数据，参与数据分片和查询负载。
  • 节点规划示例：
    • 主节点：192.168.20.16（node-master）
    • 数据节点 1：192.168.20.17（node-data-1）
    • 数据节点 2：192.168.20.18（node-data-2）
