为什么要用 Kubernetes？什么是 Kubernetes？

我们学习过 Docker，而 Docker 本身就是容器的一种解决方案。容器是镜像的一种运行状态，镜像则将应用程序进行逐层打包，使服务变得更小、更便捷、更快速移植。但当容器规模达到成百上千个时，将会遇到以下问题：

为了解决上述管理难题，Kubernetes（简称 K8S）应运而生。它负责进行统一调度与自动化管理。随着 K8S 在市场上的不断应用和迭代更新，它已成为容器编排领域的标准技术和现代云原生应用的基础设施。

本质上，K8S 是一个“智能运维助手”，一个帮你自动管理、调度、扩容、恢复容器的系统。它的核心作用是让一堆分散的容器像一个整体一样高效运转。不论遇到什么问题，它都能自动处理，帮你管理海量的容器，让应用部署变得自动化、标准化、可拓展。

其核心在于：解放人力，让开发者专注写代码，让运维不再手忙脚乱。

案例分析模块

案例 1：企业开发测试环境 K8S 集群搭建

业务背景和需求： 某互联网公司需要为开发团队搭建一个 K8S 开发测试环境，要求支持多项目并行开发、快速环境创建并有效控制成本。

解决方案：

  1. 使用 kubeadm 快速部署 3 节点集群（1 个 Master + 2 个 Worker）
  2. 使用两台服务器部署 Jenkins 和 GitLab 实现 CI/CD 流水线

实施步骤：

  1. 按照本文环境准备步骤配置基础环境。
  2. 使用 kubeadm 初始化 Master 节点。
  3. 添加两个 Worker 节点到集群中。
  4. 安装 Calico 网络插件。

效果验证： 开发团队可以快速创建测试环境，支持 10+ 个并发项目，平均环境启动时间少于 5 分钟。

案例 2：生产环境高可用 K8S 集群部署

业务背景和需求： 某金融企业需要部署生产级 K8S 集群，要求高可用、多可用区部署和严格的安全策略。

解决方案：

  1. 部署 3 个 Master 节点实现控制平面高可用。
  2. 跨多个可用区部署 Worker 节点。
  3. 配置 etcd 集群实现数据高可用。

实施步骤：

  1. 通过 HAProxy + Keepalived 实现 3 个 Master 的高可用 VIP 代理。
  2. 添加跨可用区的 Worker 节点。
  3. 配置 etcd 集群和 API Server 高可用。
  4. 部署网络插件。

效果验证： 实现 99.9% 以上的服务可用性，支持滚动升级，故障自动切换时间小于 30 秒。

常见故障排查

故障 1：集群节点状态为 NotReady

故障现象：执行 kubectl get nodes 时，节点状态显示为 NotReady。

排查方法：

  1. 检查节点上 Kubelet 服务状态：systemctl status kubelet
  2. 查看 Kubelet 日志：journalctl -u kubelet -f
  3. 检查系统资源：free -h、df -h
  4. 验证网络连通性：ping <master-ip>

解决方案：

  1. 如果 Kubelet 服务未启动，执行启动服务：systemctl start kubelet
  2. 如果镜像拉取失败，检查镜像源配置和 Docker/Containerd 状态。
  3. 如果系统资源不足，释放多余的系统资源或对节点进行扩容。
  4. 如果网络不通，检查防火墙和安全组规则。

故障 2：Pod 无法启动或 CrashLoopBackOff

故障现象：Pod 状态显示为 Pending 或 CrashLoopBackOff。

排查方法：

  1. 查看 Pod 详情：kubectl describe pod <pod-name>
  2. 查看 Pod 日志：kubectl logs <pod-name>
  3. 检查节点资源：kubectl describe node <node-name>
  4. 验证本地是否存在对应镜像：crictl images

解决方案：

  1. 若是镜像拉取失败，更新镜像地址或配置私有镜像仓库凭证。
  2. 若是资源不足，调整 Pod 的资源 limits/requests 或向集群添加新节点。
  3. 若是配置错误，修正 Pod 的 Deployment 或配置文件。
  4. 若是权限问题，检查对应的 ServiceAccount 与 RBAC 配置。

故障 3：网络通信问题

故障现象：Pod 之间无法互相通信，或 Pod 无法访问外网。

排查方法：

  1. 检查网络插件状态：kubectl get pods -n kube-system
  2. 验证网络配置：kubectl get nodes -o wide
  3. 测试 DNS 解析：kubectl run test-dns --image busybox --rm -it -- nslookup kubernetes.default
  4. 检查网络策略：kubectl get networkpolicies

解决方案：

  1. 重新安装或修复 Calico/Flannel 等网络插件。
  2. 检查 Pod Network CIDR 配置是否与物理网络冲突或配置不正确。
  3. 验证系统防火墙规则（如 iptables/ipvs）和底层网络安全组。
  4. 检查并配置正确的 NetworkPolicy
