实验 1：GPU 硬件查看（lspci）

实验目的：使用 lspci 确认操作系统识别到了 GPU 硬件，在安装任何 NVIDIA 软件之前先行验货。

覆盖技能点：lspci 识别 GPU 型号和数量

说明：本实验只使用 Linux 自带的 lspci，不依赖任何 NVIDIA 驱动。nvidia-smi 的详细操作放在实验 2 驱动安装后的验证步骤中。

步骤 1：查看系统识别的 GPU 设备

# 查看详细信息（显存大小、PCI 地址等）
lspci -v | grep -i nvidia -A 10

记录：GPU 型号、数量、每块的 PCI 地址。

步骤 3：对比 lspci 期望数量和实际数量 

1
2

# 统计系统认出的 GPU 数量
lspci | grep -i nvidia | wc -l

如果输出数量和你预期的 GPU 数量不一致，说明有 GPU 没插好或 PCIe 槽有问题。

验证方法：能说出当前机器识别到几块 GPU、什么型号、各自在哪个 PCI 地址。如果 lspci 认不到 GPU，后续安装无意义——先检查硬件。

cat > /tmp/gpu_health_check.sh << 'SCRIPT'
#!/bin/bash
echo "=== GPU 健康检查 $(date) ==="
echo "--- 设备列表 ---"
nvidia-smi -L
echo "--- 温度、功耗、显存 ---"
nvidia-smi --query-gpu=index,name,temperature.gpu,power.draw,memory.used,memory.total --format=csv,noheader
echo "--- 告警检查 ---"
nvidia-smi --query-gpu=index,temperature.gpu --format=csv,noheader | while IFS=, read idx temp; do
    temp=$(echo $temp | tr -d ' ')
    if [ "$temp" -gt 85 ]; then
        echo "警告: GPU $idx 温度 $temp°C 超过 85°C 阈值！"
    fi
done
echo "--- 运行中的进程 ---"
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv,noheader 2>/dev/null
SCRIPT
chmod +x /tmp/gpu_health_check.sh

bash /tmp/gpu_health_check.sh

验证方法：gpustat 正常输出，dmon 日志文件包含有效数据，健康检查脚本能正确判断超温告警。

步骤 3：解读关键日志

找到以下类型的日志，逐一标注其含义：

你找到的日志 含义
nvidia: loading NVIDIA UNIX x86_64 Kernel Module 驱动模块成功加载
NVRM: loading NVIDIA UNIX x86_64 Kernel Module NVRM 模块加载
nvidia_uvm: module uses symbols from nvidia UVM 模块依赖 nvidia 模块
任何 NVRM: ...error 或 Xid 消息 驱动或硬件异常

# 假设场景：nvidia-smi 报错 "Failed to initialize NVML"
# 按以下流程逐层排查：

echo "=== 第1层：硬件识别 ==="
lspci | grep -i nvidia || echo "ERROR: 系统未识别 GPU 硬件"

echo "=== 第2层：驱动模块 ==="
lsmod | grep nvidia || echo "ERROR: 驱动模块未加载"

echo "=== 第3层：驱动状态 ==="
nvidia-smi 2>&1 | head -5

echo "=== 第4层：内核日志 ==="
dmesg | grep -i "nvidia\|NVRM\|Xid" | tail -10

echo "=== 第5层：Persistenced 状态 ==="
systemctl status nvidia-persistenced 2>/dev/null | head -5

# 查看谁在用 GPU
nvidia-smi | grep -A 20 "Processes"
# 或
fuser -v /dev/nvidia* 2>/dev/null
# 有输出 = 有进程在占用 GPU，不能卸载驱动

验证方法：能独立运行完整的五层排障流程，能指出每层工具的作用和输出含义。nvidia-persistenced 服务 active 且 Persistence Mode 为 Enabled。

总结

GPU 服务器初始化是从"裸机"到"可跑大模型推理"的完整准备过程，核心链路如下：

  1. 硬件识别 — lspci 确认 GPU 在 PCIe 总线上被系统认出，nvidia-smi 确认驱动接管 GPU
  2. 驱动安装 — 禁用 nouveau → 装 NVIDIA 闭源驱动 → 重启验证，这是所有后续步骤的前提
  3. CUDA Toolkit — 装编译器 nvcc 和运行时库，让程序能用 GPU 做并行计算
  4. 运行监控 — nvidia-smi dmon 持续记录 GPU 性能，gpustat 简洁查看状态
  5. 故障排障 — lsmod 看模块、dmesg 看日志，分层排查不跳步

记住一条铁律：GPU 服务器排障从底层往上层查——硬件→驱动→CUDA→应用。不要跳过任何一层。

问题笔记

1. 拿到一台新 GPU 服务器，你的初始化步骤是什么？

  1. lspci | grep -i nvidia 确认硬件识别
  2. 检查 Secure Boot 关闭、禁用 nouveau、重启
  3. 装 NVIDIA 驱动（在线 DKMS 或 .run）、重启、nvidia-smi 验证
  4. 装 CUDA Toolkit、配置 PATH、nvcc –version 验证
  5. 装 nvidia-persistenced 保持驱动常驻
  6. pip install torch vllm 安装推理框架，验证 GPU 可用

2. nouveau 是什么？为什么要禁用？

nouveau 是 Linux 内核自带的 NVIDIA 开源驱动，由社区逆向工程实现。它和 NVIDIA 闭源驱动互相冲突——两个驱动同时想控制 GPU，会导致黑屏或驱动无法加载。装闭源驱动前必须禁用 nouveau：内核参数 nouveau.modeset=0 + modprobe 黑名单 + dracut 重建 initramfs。

3. nvidia-smi 的 CUDA Version 和 nvcc –version 一样吗？

不一样。nvidia-smi 的 CUDA Version 是驱动 API 支持的最高 CUDA 版本，nvcc –version 是实际安装的 CUDA Toolkit 版本。前者 ≥ 后者即可。很多人看到 nvidia-smi 显示 CUDA 12.8 就以为 CUDA 装好了，但 nvcc 根本没装。

4. nvidia-smi 报 “Failed to initialize NVML” 怎么排查？

按层级排查：

  1. lspci | grep -i nvidia — 硬件还在不在？
  2. lsmod | grep nvidia — 驱动模块加载了没？
  3. dmesg | grep -i nvidia — 内核日志有没有报错？
  4. 根据 dmesg 的信息决定下一步：模块没加载可能驱动坏了需重装，Secure Boot 没关需进 BIOS，Xid 错误可能是硬件故障。

5. nvidia-persistenced 是干嘛的？

GPU 空闲一段时间后，Linux 内核会自动卸载 NVIDIA 驱动模块。nvidia-persistenced 通过保持 GPU 设备文件打开，让驱动一直加载不卸载，避免下次启动 CUDA 程序时的 1-3 秒延迟。驱动 535+ 版本已弃用 nvidia-smi -pm 1，必须改用 systemd 管理 nvidia-persistenced。

7. 多 CUDA 版本共存怎么管理？

所有版本装在 /usr/local/cuda-XX/ 下，通过 /usr/local/cuda 软链接指向当前生效版本。切换版本用 ln -sfn /usr/local/cuda-12.4 /usr/local/cuda。环境变量放在 /etc/profile.d/cuda.sh，设 CUDA_HOME=/usr/local/cuda，自动跟随软链接。
