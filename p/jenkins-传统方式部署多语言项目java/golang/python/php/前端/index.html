Jenkins 传统方式部署各种语言项目主要基于每个项目独立配置的自由风格任务，通过源码管理模块拉取指定分支的代码，在构建触发器中设置轮询 SCM 或定时构建，并在构建环境中根据不同语言的技术栈执行相应的编译、测试和打包命令（如 Java 使用 Maven/Gradle 执行编译打包、Node.js 使用 npm run build 构建静态资源、Python 使用 Docker 构建镜像或直接部署脚本），最后在构建后操作中通过 SSH 插件将产物推送到目标服务器、执行部署脚本或重启服务，从而完成从代码到服务的自动化交付流程。

Jenkins 部署 Java 项目

Jenkins 部署 Java 项目通常采用 Maven 或 Gradle 作为构建工具，在流水线中配置 JDK 环境后从 Git 仓库拉取源代码，执行编译、运行单元测试和代码质量检查，然后通过 mvn package 或 gradle build 命令生成可执行的 JAR 包或 WAR 包，最后通过 SSH 插件将构建产物部署到 Tomcat 等应用服务器，或使用 Docker 构建镜像推送到镜像仓库并更新 Kubernetes 集群中的服务副本，完成从代码提交到生产部署的自动化流程。

搭建 Jenkins 构建 Java 项目

Jenkins 是一个开源的自动化服务器，可用于搭建持续集成和持续交付流程。要构建 Java 项目，首先需要安装 Jenkins 并配置 Java 环境，然后安装必要的插件如 Git、Maven 和 Pipeline，接着创建构建任务并配置源码仓库地址、构建触发器以及 Maven 构建命令，最后即可实现 Java 项目的自动化编译、测试和打包。

# 指定一个无法登录的系统用户作为启动用户
user openresty;
# 配置 worker 进程数
worker_processes auto;

# 事件配置块
events {
  # 每一个 worker 进程能够同时处理的最大进程数
  worker_connections  1024;
  # 指定 I/O 模型
  use epoll;
  # 防止惊群效应
  accept_mutex on;
  # 批量分配链接数
  multi_accept on;
}

# HTTP 配置块
http {
  # 指定字符编码
  charset utf-8;
  # 隐藏OpenResty的版本号
  server_tokens off;
  # 定义缓存路径和区域
  proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=static_cache:10m max_size=1g inactive=60m use_temp_path=off;
  # 设置日志格式
  log_format json_combined escape=json '{"timestamp":"$time_iso8601","remote_addr":"$remote_addr","remote_user":"$remote_user","request":"$request","status":"$status","body_bytes_sent":"$body_bytes_sent","request_time":"$request_time","http_referer":"$http_referer","http_user_agent":"$http_user_agent","http_x_forwarded_for":"$http_x_forwarded_for","server_name":"$server_name","server_protocol":"$server_protocol","upstream_addr":"$upstream_addr","upstream_status":"$upstream_status","upstream_response_time":"$upstream_response_time","upstream_connect_time":"$upstream_connect_time","upstream_header_time":"$upstream_header_time","request_length":"$request_length","request_method":"$request_method","uri":"$uri","query_string":"$query_string","http_host":"$http_host","scheme":"$scheme","gzip_ratio":"$gzip_ratio","connection":"$connection","connection_requests":"$connection_requests","pipe":"$pipe"}';
  # 设置日志的路径
  access_log /var/log/openresty/access.log json_combined;
  # 错误日志
  error_log /var/log/openresty/error.log warn;
  # 启用 gzip 压缩
  gzip on;
  # 压缩级别：1-9，推荐 4-6
  gzip_comp_level 6;
  # 最小压缩文件大小
  gzip_min_length 1k;
  # 压缩缓冲区
  gzip_buffers 4 16k;
  # 压缩协议版本
  gzip_http_version 1.0;
  # 对代理请求启用压缩
  gzip_proxied any;
  # 在响应头添加 Vary: Accept-Encoding
  gzip_vary on;
  # 指定需要压缩的 MIME 类型
  gzip_types text/css text/xml text/javascript;
  # 载入 OpenResty 能够识别的文件的类型
  include mime.types;
  # OpenResty 无法识别文件类型时，默认的文件类型
  default_type  application/octet-stream;
  # 提升系统文件句柄效率
  sendfile        on;
  # 65秒无请求则关闭连接
  keepalive_timeout 65s;
  # 最多处理1000个请求后关闭连接
  keepalive_requests 1000;
  # 合并数据包发送
  tcp_nopush on;
  # 减少交互延迟
  tcp_nodelay on;
  # 载入外部的HTTP配置块内部的配置
  include /usr/local/openresty/nginx/conf/conf.d/*.conf;
}

[uwsgi]
# 基本项目配置
project = myflaskapp
base_dir = /data/python
wsgi-file = %(base_dir)/app.py
callable = app
chdir = %(base_dir)

# 基础进程配置
workers = 2
threads = 2

# 网络配置
socket = /run/uwsgi/%(project).sock
chmod-socket = 660
chown-socket = openresty:openresty

# 日志配置
logto = /var/log/uwsgi/%(project).log
logto2 = /var/log/uwsgi/%(project)_error.log

# 权限设置
uid = openresty
gid = openresty

# 运行控制
pidfile = /run/uwsgi/%(project).pid
daemonize = /var/log/uwsgi/%(project)_daemon.log
vacuum = true

# 环境变量
env = PYTHONPATH=%(base_dir)
env = FLASK_ENV=production

# Laravel 项目的 Server 配置（核心）
server {
    listen       80;
    listen       [::]:80;
    server_name  laravel.example.com;
    root         /data/your-project-name/public;
    index        index.php index.html index.htm;

    # 字符编码配置
    charset utf-8;

    # Laravel URL 重写
    location / {
        try_files $uri $uri/ /index.php?$query_string;
        expires -1;
    }

    # PHP 解析配置（对接 PHP-FPM）
    location ~ \.php$ {
        fastcgi_pass   127.0.0.1:9000;
        fastcgi_index  index.php;
        fastcgi_param  SCRIPT_FILENAME  $realpath_root$fastcgi_script_name;
        include        fastcgi_params;
        
        # Laravel 必需的 FastCGI 参数
        fastcgi_param  PATH_INFO $fastcgi_path_info;
        fastcgi_param  APP_ENV production;
        fastcgi_param  APP_DEBUG false;
    }

    # 禁止访问隐藏文件
    location ~ /\.(?!well-known).* {
        deny all;
        access_log off;
        log_not_found off;
    }

    # 禁止访问 Laravel 敏感目录
    location ~ /(storage|vendor|bootstrap/cache) {
        deny all;
        access_log off;
        log_not_found off;
    }
}

配置 Jenkins 自动化发布

(此处可以根据您的项目发布步骤添加具体构建后操作配置)

Jenkins 部署 前端 项目

Jenkins 就像一个不知疲倦的自动化部署机器人。当你写好前端代码（比如 Vue 或 React 项目）并提交到代码仓库（如 Git）后，Jenkins 就会被触发启动。它会按照你预设的“流水线脚本”一步步执行任务：首先拉取最新的代码，然后安装项目依赖（比如执行 npm install），接着运行构建命令（如 npm run build）将源代码打包压缩成浏览器能直接运行的 HTML、CSS、JS 等静态文件。最后，Jenkins 会通过 SSH 或 FTP 等方式，将这些构建好的“成品”文件自动上传到你的 Web 服务器（如 Nginx）的指定目录下。这样一来，整个从代码提交到线上更新的过程就实现了全自动化，极大地提高了部署的效率和可靠性。
