创建告警规则

创建一个告警规则文件，例如<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">linux_host_alerts.rules</font>，并添加以下规则。

groups:
- name: linux_host_alerts  # 告警规则组名
  rules:
  # 规则1: 监控主机关机或失联
  - alert: InstanceDown
    expr: up{job="node"} == 0  # up指标为0表示目标无法访问
    for: 1m  # 条件持续1分钟才触发告警，避免网络抖动误报
    labels:
      severity: critical  # 设置告警级别为严重
    annotations:
      summary: "主机 {{ $labels.instance }} 失联"
      description: "{{ $labels.instance }} 已关机或无法连接超过1分钟，请立即检查。"

  # 规则2: 监控CPU使用率超过50%
  - alert: HighCPUUsage
    expr: 100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 50
    for: 5m  # 条件持续5分钟触发，避免瞬时负载误报
    labels:
      severity: warning
    annotations:
      summary: "主机 {{ $labels.instance }} CPU使用率过高"
      description: "{{ $labels.instance }} 的CPU使用率已超过50%并持续5分钟，当前值为 {{ $value | printf \"%.2f\" }}%。"

关键点说明：

  • **<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">up == 0</font>**：<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">up</font>指标是Prometheus自动生成的，用于判断抓取目标是否健康。
  • CPU使用率计算：
    • <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">node_cpu_seconds_total{mode="idle"}</font>：获取CPU空闲时间的计数器。
    • <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">rate(...[5m])</font>：计算5分钟内每秒CPU空闲时间的平均增长率。
    • <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">avg by (instance) ... * 100</font>：计算每个实例的平均CPU空闲率，并转换为百分比。
    • <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">100 - ...</font>：用100减去空闲率，得到CPU使用率。

# =============================================================================
# Alertmanager 全局配置
# =============================================================================
global:
  # SMTP 服务器地址和端口
  # 格式: '主机名:端口'
  # 465端口是SSL加密端口，587端口是STARTTLS端口
  smtp_smarthost: 'smtp.163.com:465'
  
  # 发件人邮箱地址
  # 必须与smtp_auth_username一致或属于同一账户
  smtp_from: 'chenyangqit@163.com'
  
  # SMTP认证用户名（通常是完整的邮箱地址）
  smtp_auth_username: 'chenyangqit@163.com'
  
  # SMTP认证密码或授权码
  # 对于163邮箱，需要使用授权码而不是登录密码
  # 授权码可以在邮箱设置中生成
  smtp_auth_password: 'PTsexxxxx95panw'
  
  # 是否要求TLS加密
  # 使用465端口时设为false（因为465端口使用隐式SSL）
  # 使用587端口时设为true（因为587端口使用显式STARTTLS）
  smtp_require_tls: false

# =============================================================================
# 告警路由配置
# =============================================================================
route:
  # 告警分组依据的标签列表
  # 具有相同这些标签值的告警会被分到同一组
  group_by: ['alertname', 'cluster']
  
  # 初次等待时间：当第一个告警到达后，等待多长时间才发送通知
  # 这样可以将同一时间段的多个相关告警合并发送
  group_wait: 10s
  
  # 组间隔时间：在发送第一个通知后，等待多长时间才发送更新的通知
  # 用于控制告警更新的频率
  group_interval: 10s
  
  # 重复间隔：如果告警持续触发，重复发送通知的时间间隔
  # 避免对持续存在的问题发送过多通知
  repeat_interval: 1h
  
  # 默认接收器：当告警不匹配任何子路由时使用的接收器
  receiver: 'email-163'
  
  # 子路由规则列表（按顺序匹配）
  routes:
    # 第一条子路由：处理严重( critical )级别的告警
    - matchers:
        # 匹配条件：severity标签值为"critical"
        # 语法说明：
        # =   : 精确等于
        # !=  : 不等于  
        # =~  : 正则匹配
        # !~  : 正则不匹配
        - severity="critical"
      
      # 使用哪个接收器发送通知
      receiver: 'email-163'
      
      # 严重告警的组间隔更短（30秒），响应更快
      group_interval: 30s
      
      # 严重告警的重复间隔更短（10分钟），提醒更频繁
      repeat_interval: 10m
      
      # 严重告警的分组方式：只按告警名称分组
      # 这样每个严重告警都会单独发送，不会被其他标签分组
      group_by: [alertname]
      
      # 是否继续匹配后续路由
      # false: 匹配到此路由后停止继续匹配
      # true:  匹配到此路由后继续匹配其他路由
      continue: false

# =============================================================================
# 模板文件配置
# =============================================================================
templates:
  # 自定义模板文件路径
  # 支持通配符，如: "/etc/alertmanager/template/*.tmpl"
  # 模板文件用于定义邮件主题、HTML内容、文本内容等的格式
  - "/etc/alertmanager/template/email-html.tmpl"

# =============================================================================
# 接收器配置
# =============================================================================
receivers:
  # 接收器名称，在路由中引用
  - name: 'email-163'
    
    # 邮件配置列表（可以配置多个邮件接收配置）
    email_configs:
    - to: "chenyangqit@163.com"  # 收件人邮箱地址
      
      # 是否在告警恢复时发送解决通知
      send_resolved: true
      
      # 邮件头配置
      headers:
        # 邮件主题模板
        # 使用模板语法动态生成主题
        # {{ template "email.custom.subject" . }} 调用自定义主题模板
        # . 表示传递给模板的上下文数据
        Subject: '{{ template "email.custom.subject" . }}'
      
      # HTML格式的邮件内容模板
      # 用于支持HTML的邮件客户端显示富文本内容
      html: '{{ template "email.custom.html" . }}'
      
      # 纯文本格式的邮件内容模板  
      # 用于不支持HTML的邮件客户端或作为备选显示
      # 提供更好的兼容性
      text: '{{ template "email.custom.text" . }}'

# =============================================================================
# 配置说明总结
# =============================================================================
# 1. 邮件服务：使用163邮箱SMTP服务，465端口SSL加密
# 2. 路由策略：
#    - 默认分组：按告警名称和集群分组
#    - 严重告警：单独处理，响应更快，提醒更频繁
# 3. 通知频率：
#    - 普通告警：最多每小时重复一次
#    - 严重告警：最多每10分钟重复一次
# 4. 邮件内容：使用自定义模板，支持HTML和纯文本双版本
# 5. 恢复通知：告警解决时会发送恢复通知

/etc/alertmanager/template/email-html.tmpl

模版语法参考文档：https://prometheus.io/docs/alerting/latest/notifications/

模板中的数据与结构

在 Alertmanager 的模板中，<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">.</font> 代表当前传递给模板的上下文数据，主要包含以下信息（你可以利用这些数据来构建通知内容）：

字段名称 描述
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">Receiver</font> 接收器的名称，例如 “email-163”。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">Status</font> 告警组的状态，通常是 “firing” 或 “resolved”。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">Alerts</font> 一个数组，包含了此通知中所有告警的详细信息。**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">{{ range .Alerts }}</font>**
****就是用来遍历这个数组的。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">GroupLabels</font> 一个键值对，包含了用于分组的标签。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">CommonLabels</font> 一个键值对，包含了此告警组中所有告警共有的标签。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">CommonAnnotations</font> 一个键值对，包含了此告警组中所有告警共有的注释。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">ExternalURL</font> 用于链接回 Alertmanager 的地址。

在 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">{{ range .Alerts }}</font> 循环内部，每个独立的告警（通常用 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">.</font> 表示）又包含以下常用字段：

字段名称 描述
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">Status</font> 单个告警的状态，例如 “firing” 或 “resolved”。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">Labels</font> 包含此告警所有标签的键值对。常用标签如 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">alertname</font>, <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">instance</font>, <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">severity</font> 等。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">Annotations</font> 包含此告警所有注释的键值对。常用注释如 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">summary</font>, <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">description</font>等。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">StartsAt</font> 告警开始的时间。这是一个 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">time.Time</font>对象，可以用 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">.StartsAt.Format "2006-01-02 15:04:05"</font>来格式化显示时间。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">EndsAt</font> 告警预期结束的时间（对于已恢复的告警尤其有用）。
<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">GeneratorURL</font> 一个URL，可以链接到生成此告警的 Prometheus 表达式。

告警参数详细解释

**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">group_by: ['alertname', 'cluster']</font>**

  • 作用：定义告警分组的依据字段
  • 效果：
    • 相同 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">alertname</font>（告警名称）和 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">cluster</font>（集群）的告警会被合并到同一通知中
    • 例如：<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">CPU使用率高</font>告警 + <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">生产集群</font> = 一个分组
    • 避免同一问题的多个实例产生大量独立通知（意思是一个集群中，多个服务器产生了告警，合并成一条告警通知；如果没有这个分组，则会有多少台机器，就发多少个告警信息）

**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">group_wait: 10s</font>**

  • 作用：等待时间，收集同一分组的初始告警
  • 工作流程：
    • 当第一个告警触发时开始计时
    • 在10秒内，同一分组的其他告警会被收集
    • 10秒后发送包含所有收集到的告警的合并通知
  • 好处：防止告警风暴，批量发送相关告警

**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">group_interval: 10s</font>**

  • 作用：同一分组内新告警的发送间隔
  • 场景：
    • 分组通知已发送后，如果该分组又有新告警产生
    • 必须等待至少10秒才会发送包含新告警的更新通知
  • 目的：控制同一分组内告警更新的频率

**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">repeat_interval: 1h</font>**

  • 作用：重复发送相同告警的间隔时间
  • 场景：
    • 对于持续存在的告警（未恢复）
    • 每隔1小时重新发送一次提醒
  • 重要性：
    • 防止遗忘未处理的告警
    • 避免过于频繁的重复通知造成干扰

**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">receiver: 'email-163'</font>**

  • 作用：指定默认的消息接收器
  • 关联：需要与 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">receivers</font> 部分定义的接收器名称对应

子路由基本概念

2

routes:

  # 子路由会继承父路由的配置，但可以覆盖特定参数

匹配条件 (match / match_re)

<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">match</font> - 精确匹配 

1
2
3

- match:
    severity: critical
    cluster: production
  • 作用：精确匹配告警的标签值
  • 要求：告警必须包含所有指定的标签和对应的精确值
  • 示例：只匹配 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">severity=critical</font> 且 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">cluster=production</font> 的告警

<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">match_re</font> - 正则匹配 

1
2
3

- match_re:
    service: ^(mysql|redis|mongodb)
    instance: .*-db-.*
  • 作用：使用正则表达式匹配告警标签值
  • 灵活性：可以匹配模式相似的一组服务
  • 示例：匹配 service 标签为 mysql、redis 或 mongodb 的告警

接收器配置 (receiver) 

1

receiver: 'critical-alerts'
  • 作用：指定匹配到的告警发送到哪个接收器
  • 要求：必须在 <font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">receivers</font> 部分有对应的接收器定义

分组配置覆盖 (group_by) 

1

group_by: [service]
  • 作用：覆盖父路由的分组策略
  • 效果：按服务名称分组，而不是按告警名称和集群
  • 好处：同一服务的不同告警会被合并通知

时间间隔覆盖 

1
2

group_interval: 5s
repeat_interval: 10m
  • 作用：针对特定类型的告警调整通知频率
  • 灵活性：重要告警可以设置更频繁的通知

# 当两个告警的 alertname 和 instance 相同时，严重告警（severity="critical"）抑制 普通告警（severity="warning"）

  - source_matchers: [severity="critical"]
    target_matchers: [severity="warning"]
    equal:
      - alertname
      - instance
