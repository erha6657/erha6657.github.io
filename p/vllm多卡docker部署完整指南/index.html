模型加载参数详解

–model（必填）

指定模型路径，可以是：

  • Hugging Face ID：Qwen/Qwen2-7B-Instruct

常用参数速查表

参数 默认值 说明 调优建议
**--model** 必填 模型路径 使用本地路径更快
**--tensor-parallel-size** 1 张量并行GPU数 多卡时设置
**--gpu-memory-utilization** 0.9 GPU显存利用率 测试0.9，生产0.95
**--max-model-len** 自动 最大上下文长度 根据显存调整
**--max-num-seqs** 256 最大并发序列数 高并发时增大
**--host** 127.0.0.1 监听地址 生产用0.0.0.0
**--port** 8000 服务端口 避免冲突
**--trust-remote-code** False 信任远程代码 Qwen等需要

理解显存使用

GPU显存分配
├── 模型权重（固定）
│   └── 7B FP16 ≈ 14GB
├── KV Cache（动态）
│   ├── PagedAttention管理
│   └── 随并发和上下文长度增长

作用：控制vLLM使用的GPU显存比例

选择建议

场景 推荐值 原因
测试开发 0.9 平衡性能和稳定性
生产环境 0.95 最大化资源利用
显存紧张 0.8 避免OOM
多服务共存 0.7 给其他服务留空间

max-model-len 参数

作用：设置模型的最大上下文长度（Token数）

1
2
3
4

6

# 设置最大上下文为4096 tokens
--max-model-len 4096

# 设置最大上下文为8192 tokens
--max-model-len 8192

# 设置最大上下文为32768 tokens（长文本场景）
--max-model-len 32768

上下文长度与显存关系

上下文长度 额外显存需求（7B） 适用场景
2048 约2GB 简单对话
4096 约4GB 日常使用
8192 约8GB 文档处理
16384 约16GB 长文本分析
32768 约32GB 超长文档

💡** 重要提示**：上下文长度越大，KV Cache占用显存越多。根据实际需求设置，不要盲目追求最大值。

作用：设置同一时刻最大处理的序列数（并发请求数）

# 24GB显存机器建议：128-256 并发
# 80GB显存机器建议：256-512 并发

enable-chunked-prefill 参数（重要）

作用：启用分块预填充，提升吞吐量

1
2

# 启用分块预填充（生产环境推荐）
--enable-chunked-prefill

什么是分块预填充？

  • 传统方式：处理长上下文时，会阻塞其他请求
  • 分块预填充：将长上下文切分成小块，交替处理

性能提升

场景 吞吐量提升 延迟变化
长短请求混合 20-40% 短请求延迟降低
请求长度均匀 10-20% 基本不变

单机多卡部署

什么时候需要多卡

场景一：单卡显存不够

1
2
3

70B模型 FP16 ≈ 140GB
单张A100 80GB → 放不下
需要 2张A100 80GB → 每张70GB，可以放下

场景二：提升吞吐量

1
2

单卡处理能力：50 tokens/s
4卡并行：150-200 tokens/s（接近线性扩展）

场景三：高可用（多副本）

1
2

单卡故障 → 服务中断
多卡多副本 → 单卡故障不影响服务

张量并行（Tensor Parallelism）概念

什么是张量并行？

将模型的参数切分到多张GPU上，每张GPU只存储和处理部分参数。

类比理解

【类比】张量并行就像多人搬运大件物品：

  • 一个人搬不动700斤的柜子
  • 4个人一起搬，每人承担175斤
  • 大家协调配合，一起完成任务

与数据并行的区别

特性 张量并行 数据并行
模型存储 切分到多卡 每卡完整模型
适用场景 模型太大单卡放不下 提升吞吐量
通信开销 较高 较低
vLLM支持 ✅** tensor-parallel-size** ❌** 不支持**

#!/bin/bash
# performance_test.sh - vLLM性能测试脚本

VLLM_URL="http://localhost:8000/v1/chat/completions"
MODEL="Qwen/Qwen2-7B-Instruct"

echo "=== vLLM性能测试 ==="
echo "服务地址: $VLLM_URL"
echo "模型: $MODEL"
echo ""

# 测试1：单次请求延迟
echo "=== 测试1：单次请求延迟 ==="
START=$(date +%s.%N)
RESPONSE=$(curl -s "$VLLM_URL" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"$MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}],\"max_tokens\":50}")
END=$(date +%s.%N)

LATENCY=$(awk "BEGIN {printf \"%.3f\", $END - $START}")
TOKENS=$(echo "$RESPONSE" | jq -r '.usage.completion_tokens // 0')
SPEED=$(awk "BEGIN {printf \"%.1f\", $TOKENS / $LATENCY}" 2>/dev/null || echo "N/A")

echo "延迟: ${LATENCY}s"
echo "生成Tokens: $TOKENS"
echo "生成速度: ${SPEED} tokens/s"
echo ""

# 测试2：不同长度请求
echo "=== 测试2：不同长度请求对比 ==="
for LEN in 50 100 200 500; do
  START=$(date +%s.%N)
  RESP=$(curl -s "$VLLM_URL" \
    -H "Content-Type: application/json" \
    -d "{\"model\":\"$MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"请写一个${LEN}字左右的短文\"}],\"max_tokens\":$LEN}")
  END=$(date +%s.%N)

  LAT=$(awk "BEGIN {printf \"%.3f\", $END - $START}")
  TOK=$(echo "$RESP" | jq -r '.usage.completion_tokens // 0')
  SPD=$(awk "BEGIN {printf \"%.1f\", $TOK / $LAT}" 2>/dev/null || echo "N/A")
  echo "max_tokens=$LEN: 延迟=${LAT}s, tokens=$TOK, 速度=${SPD} tokens/s"
done
echo ""

# 测试3：并发测试（简单版）
echo "=== 测试3：并发测试（10个并发请求）==="
START=$(date +%s.%N)
for i in {1..10}; do
  curl -s "$VLLM_URL" \
    -H "Content-Type: application/json" \
    -d "{\"model\":\"$MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"请求$i: 你好\"}],\"max_tokens\":20}" \
    > /dev/null &
done
wait
END=$(date +%s.%N)
TOTAL=$(awk "BEGIN {printf \"%.3f\", $END - $START}")
echo "10个并发请求总耗时: ${TOTAL}s"
echo "平均每请求: $(awk "BEGIN {printf \"%.2f\", $TOTAL / 10}")s"

性能调优建议

问题 现象 解决方案
GPU利用率低 <50% 增大max-num-seqs，启用chunked-prefill
显存不足 OOM错误 降低gpu-memory-utilization，减小max-model-len
首字延迟高 TTFT>2s 检查模型加载，减少并发
吞吐量低 tokens/s<30 增加并发，使用多卡
请求排队 等待时间长 增加副本数，负载均衡
